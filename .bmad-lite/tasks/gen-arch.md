# Generate Architecture Docs Task

Generate Architecture documentation from scan results.
Referenced from `.bmad-lite/agents/scanner.md`.

---

## Prerequisites

- `*scan-arch` or `*scan` must be completed first
- Scan data available: config, tech, structure, models, routes

## Template

Uses architecture section structure from `.bmad-lite/templates/architecture.yaml` as reference for file naming and structure.

## Output Files

```
docs/architecture/
  index.md                        # TOC with links
  tech-stack.md                   # [SCANNED] categorized dependency table with versions
  source-tree.md                  # [SCANNED] annotated folder tree
  source-tree.json                # [SCANNED] machine-readable file paths
  data-models.md                  # [SCANNED] entity names, fields, relations
  rest-api-spec.md                # [SCANNED] endpoints grouped by domain
  coding-standards.md             # [SCANNED] inferred from eslint/prettier/tsconfig
  database-schema.md              # [SCANNED] collections/tables from model analysis
  security.md                     # [SCANNED] auth method, RBAC roles, middleware
  components.md                   # [SCANNED] component names grouped by folder
docs/
  module-graph.md                 # [SCANNED] module relationships + Mermaid diagram
```

### source-tree.md (from scan-structure)

Use tree-drawing characters (`├──`, `│`, `└──`) inside a fenced code block.
Each line = one folder with inline `# annotation`.
Reference: `docs/architecture/source-tree.md` in existing projects.

```markdown
# Source Tree

> [SCANNED] Folder-level overview only. For exact file paths, see [`source-tree.json`](./source-tree.json).

{tree-character folder tree with inline # annotations}
```

### source-tree.json (from scan-structure)

Nested JSON object — each folder is a key, files listed in `_files` arrays.
For large folders (>6 files), list all individual file names.
Reference: `docs/architecture/source-tree.json` in existing projects.

```json
{
  "src": {
    "folderName": {
      "subFolder": {
        "_files": ["file1.ts", "file2.ts"]
      },
      "_files": ["root-file.ts"]
    }
  }
}
```

### module-graph.md (from scan-modules + architecture files)

**Template:** `.bmad-lite/templates/module-graph.yaml`

After ALL architecture files are generated, create `docs/module-graph.md`:

```markdown
# Module Relationship Graph

> [SCANNED] Auto-generated by BMad-Lite Scanner. Review and refine with `/bmad-plan arch`.
>
> Last updated: {date}

## Architecture Overview

```mermaid
graph TB
    subgraph DOMAIN_A["{Domain A}"]
        MOD_A1[{Module}<br/>{detail}]
    end

    subgraph DOMAIN_B["{Domain B}"]
        MOD_B1[{Module}<br/>{detail}]
    end

    %% Relationships
    MOD_A1 --> MOD_B1
```

## Module Details & Story References

### {Domain A}
| Module | Key Files | Related Stories |
|--------|-----------|-----------------|
| {Module} | `{path}` | [TODO] |

### Shared / Cross-cutting
| Module | Key Files | Related Stories |
|--------|-----------|-----------------|
| {SharedModule} | `{path}` | [TODO] |

## How to Use This Graph

**When adding a new feature:**
1. Identify which module(s) in the graph are affected
2. Follow the arrows to find related modules that may need updates
3. Read the related stories to understand existing patterns and decisions
4. Check `source-tree.json` for exact file paths in those modules
```

**Derivation:**
- Subgraphs: group modules by domain from `components.md` + `data-models.md`
- Nodes: one per entity/service detected in scan
- Arrows: inferred from model relations + route dependencies
- Key Files: from `source-tree.json`
- Stories: `[TODO]` (populated later by Planner or Reviewer)
