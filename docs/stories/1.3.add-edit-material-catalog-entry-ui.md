# Story 1.3: Add & Edit Material Catalog Entry UI

**Status:** Done
**Epic:** Material Catalog Foundation
**Created:** 2026-05-23
**Last Updated:** 2026-05-23

## Story

**As a** Farm Manager,
**I want** a clear form to create and modify catalog items,
**so that** I can keep our material inventory directory up to date.

## Acceptance Criteria

1. Given the Catalog Form modal, When the user leaves required fields empty and submits, Then the UI must highlight the invalid fields and prevent submission.
2. Given an existing catalog item, When the user modifies its name or threshold and saves, Then it must send a PUT request to the API and update the catalog list in real-time.

## Tasks

- [ ] Task 1: Implement the PUT serverless API endpoint for material catalog items (AC: 2)
  - [ ] Create `src/app/api/materials/[id]/route.ts` with support for `PUT` method
  - [ ] Implement simulated role-based authorization check for header `x-user-role` matching `Manager` or `FarmManager`
  - [ ] Parse and validate the request body using a Zod schema (validating name, type, uom, safetyStock)
  - [ ] Verify that name updates do not cause a duplicate name collision with other catalog records
  - [ ] Return the updated material in the standardized typed envelope `IApiResponse<IMaterial>`
- [ ] Task 2: Build the validation schema and Catalog Form Modal component (AC: 1, 2)
  - [ ] Design a beautiful glassmorphic modal matching the dark theme layout specs
  - [ ] Integrate form state control using `react-hook-form` paired with a Zod validator schema
  - [ ] Set up real-time error indicators highlighting invalid/missing required fields in high-visibility red font and glowing red input borders
  - [ ] Prevent form submission when errors exist and show helpful inline messages
  - [ ] Bind loading status to the submit button, showing an elegant loader spinner and disabling actions during async mutation
- [ ] Task 3: Integrate Form Actions into the Catalog UI Screen (AC: 1, 2)
  - [ ] Update `src/app/catalog/page.tsx` header to add a glowing "+ Add Supply" button
  - [ ] Add an action column with an "Edit" button (using a clean cog/pencil SVG icon) for each row in the catalog table
  - [ ] Set up state hooks to handle modal visibility and "Add" vs "Edit" pre-populated form context
  - [ ] Define TanStack Query mutations (`useMutation`) for both `POST /api/materials` and `PUT /api/materials/:id`
  - [ ] On mutation success, invoke `queryClient.invalidateQueries` for query key `queryKeys.materials.all` to trigger real-time UI catalog list updates
- [ ] Task 4: Implement tests and verify Gherkin acceptance criteria (AC: 1, 2)
  - [ ] Write integration tests in `tests/integration/api/materials.[id].test.ts` checking PUT auth guards, proper field updates, and name duplication errors
  - [ ] Verify frontend validations correctly reject empty required parameters
  - [ ] Conduct manual visual walkthroughs to ensure premium UX transitions, modal accessibility (Escape key to close, focus traps), and smooth animations

### Data Models

- IMaterial:
  - `id`: string
  - `name`: string (unique, required)
  - `type`: MaterialType ('Seeds' | 'Fertilizers' | 'Pesticides' | 'Tools', required)
  - `uom`: string (required)
  - `safetyStock`: number (required, >= 0)
  - `currentStock`: number (required, >= 0, default 0)
  - `createdAt`: Date
  - `updatedAt`: Date
  [Source: docs/architecture/data-models.md]

### API Endpoints

- `POST /api/materials` - Create a new catalog material item (Simulated authorization: x-user-role: Manager/FarmManager)
  [Source: docs/architecture/rest-api-spec.md]
- `PUT /api/materials/:id` - Edit safety threshold and name of an existing item (Simulated authorization: x-user-role: Manager/FarmManager)
  [Source: docs/architecture/rest-api-spec.md]

### Testing Requirements

- Integration tests: PUT requests must fail if simulated role headers are missing or not administrative.
- Integration tests: PUT requests must fail if updated `name` collides with another material.
- Visual/Manual test: Catalog list refetches automatically and smoothly upon successful form submission without a full-page reload.
  [Source: docs/architecture/test-strategy-and-standards.md]

### Coding Standards

- Complete Type Safety: No `any` keyword. Strongly typed React custom hooks and React Query mutations.
- Dual-Layer Validation: Zod schemas enforcing requirements on the client forms and again at serverless API boundaries.
- Standardized typed JSON envelope structure `IApiResponse<T>` for all API returns.
  [Source: docs/architecture/coding-standards.md]
