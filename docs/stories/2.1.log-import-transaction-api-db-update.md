# Story 2.1: Log Import Transaction API & DB Update

**Status:** Done
**Epic:** Import Transactions & Stock Accounting
**Created:** 2026-05-23
**Last Updated:** 2026-05-23

## Story

**As a** Warehouse Operator,
**I want** an API endpoint to record incoming shipments,
**so that** inventory balances are incremented and shelf-life tracking is established.

## Acceptance Criteria

1. Given a POST request to `/api/imports`, When payload contains valid transaction attributes (date, supplier, materialId, quantity, unitPrice, batchCode, expirationDate), Then it must write an import log entry and increment the material's total stock level in the database.
2. Given an import payload, When `quantity` or `unitPrice` is zero/negative, Then it must return a `400 Bad Request` validation error.

### Data Models

- IImport:
  - `id`: string (PK, MongoDB ObjectId)
  - `date`: Date (required)
  - `supplierName`: string (required)
  - `materialId`: string (FK -> Material, required)
  - `quantity`: number (required, > 0)
  - `unitPrice`: number (required, > 0)
  - `batchCode`: string (optional)
  - `expirationDate`: Date (optional)
  - `createdAt`: Date
  - `updatedAt`: Date
  [Source: docs/architecture/data-models.md]

- IMaterial:
  - `id`: string
  - `name`: string (unique, required)
  - `type`: MaterialType ('Seeds' | 'Fertilizers' | 'Pesticides' | 'Tools', required)
  - `uom`: string (required)
  - `safetyStock`: number (required, >= 0)
  - `currentStock`: number (required, >= 0, default 0)
  - `createdAt`: Date
  - `updatedAt`: Date
  [Source: docs/architecture/data-models.md]

### API Endpoints

- `POST /api/imports` - Record a new incoming stock delivery and increment stock-on-hand
  [Source: docs/architecture/rest-api-spec.md]
- `GET /api/imports` - List all incoming transaction records, sorted by date descending
  [Source: docs/architecture/rest-api-spec.md]
