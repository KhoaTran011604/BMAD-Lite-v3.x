# Story 4.1: Live Stock On Hand View

**Status:** Done
**Epic:** Live Inventory & Smart Alerts Dashboard
**Created:** 2026-05-23
**Last Updated:** 2026-05-23

## Story

**As a** Farm Manager,
**I want** an analytical dashboard showing total active stocks and total catalog value,
**so that** I can quickly evaluate our current physical assets.

## Acceptance Criteria

1. Given the Dashboard home, When loaded, Then it must display key highlight counters: Total Materials, Active Alerts, and Total Portfolio Value (calculated as sum of `stockOnHand * averageUnitPrice`).
2. Given stock list cards, When stock level changes (due to background transactions), Then the numbers must update reactively.

## Tasks

- [x] Replace the placeholder dashboard in `src/app/page.tsx` with a data-driven LiveDashboardUI layout that renders KPI cards, a stock summary list, and loading/error states. (AC: 1, 2)
- [x] Build dashboard queries using TanStack Query with centralized query keys, separating read logic from UI rendering. (AC: 1, 2)
- [x] Add backend data composition for dashboard metrics by combining materials, imports, and exports data needed to calculate total materials, active alerts, and portfolio value. (AC: 1)
- [x] Define a deterministic average unit price strategy based on recorded import transactions and use it in portfolio value calculation. (AC: 1)
- [x] Ensure dashboard values refresh after import/export mutations invalidate relevant query keys and refetch successfully. (AC: 2)
- [x] Add unit and integration coverage for dashboard metric calculations and API-backed loading behavior. (AC: 1, 2)

### Data Models

- `IMaterial`: includes `id`, `name`, `type`, `uom`, `safetyStock`, `currentStock`, `createdAt`, `updatedAt`. [Source: docs/architecture.md#data-models]
- `IImport`: includes `materialId`, `quantity`, `unitPrice`, `batchCode`, `expirationDate`, and timestamps. [Source: docs/architecture.md#data-models]
- `IExport`: includes `materialId`, `quantity`, `destinationPurpose`, and timestamps. [Source: docs/architecture.md#data-models]

### API Endpoints

- `GET /api/materials` - Lists all materials sorted alphabetically; suitable for stock-on-hand and low-stock counts. [Source: docs/architecture.md#rest-api-spec]
- `GET /api/imports` - Lists import transactions sorted by date descending; needed for portfolio value inputs. [Source: docs/architecture.md#rest-api-spec]
- `GET /api/exports` - Lists export transactions sorted by date descending; supports reactive dashboard refresh behavior. [Source: docs/architecture.md#rest-api-spec]

### Technical Constraints

- Use Next.js App Router with TypeScript 5.3.x and TanStack React Query v5 only. [Source: docs/architecture.md#tech-stack]

- Query hooks and mutation hooks must be decoupled per module. [Source: docs/architecture.md#coding-standards]
- All query keys must be centralized in a key factory. [Source: docs/architecture.md#coding-standards]
- No `any` is allowed anywhere in the implementation. [Source: docs/architecture.md#coding-standards]
