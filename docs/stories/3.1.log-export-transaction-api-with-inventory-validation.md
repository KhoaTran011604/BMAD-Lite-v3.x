# Story 3.1: Log Export Transaction API with Inventory Validation

**Status:** Done
**Epic:** Export Transactions & Inventory Safety
**Created:** 2026-05-23
**Last Updated:** 2026-05-23

## Story

**As a** Warehouse Operator,
**I want** an export API that performs a transaction check on available stock,
**so that** I cannot disburse more items than are physically present.

## Acceptance Criteria

1. Given a POST request to `/api/exports`, When requested quantity is less than or equal to current stock-on-hand, Then it must successfully record the export and subtract the quantity from stock.
2. Given a POST request to `/api/exports`, When requested quantity exceeds current stock-on-hand, Then it must reject the request with a `400 Bad Request` and return an error message: "Insufficient stock available".

### Data Models

- IExport:
  - `id`: string (PK, MongoDB ObjectId)
  - `date`: Date (required)
  - `requesterName`: string (required)
  - `materialId`: string (FK -> Material, required)
  - `quantity`: number (required, > 0)
  - `destinationPurpose`: string (required)
  - `createdAt`: Date
  - `updatedAt`: Date
  [Source: docs/architecture/data-models.md]

- IMaterial:
  - `id`: string
  - `name`: string (unique, required)
  - `type`: MaterialType ('Seeds' | 'Fertilizers' | 'Pesticides' | 'Tools', required)
  - `uom`: string (required)
  - `safetyStock`: number (required, >= 0)
  - `currentStock`: number (required, >= 0, default 0)
  - `createdAt`: Date
  - `updatedAt`: Date
  [Source: docs/architecture/data-models.md]

### API Endpoints

- `POST /api/exports` - Record a new stock disbursement with stock availability checks

### Coding Standards

- Complete Type Safety: The `any` keyword is strictly prohibited.
- Backend requests must be validated with Zod at the API route boundary.
- API responses must use the standardized typed envelope structure `IApiResponse<T>`.
- The system must never accept an export transaction that exceeds available stock on hand.
